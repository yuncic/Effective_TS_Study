# 아이템2 타입스크립트 설정 이해하기

타입스크립트 컴파일러는 매우 많은 설정을 가지고 있다.
이 설정들을 커맨드 라인(터미널), tsconfig.json 설정 파일을 통해서 사용 가능하다.

TS를 어떻게 사용할 계획인지 동료들이나 다른 도구들에서 알기 편하도록 가급적 설정 파일을 사용하는 것이 좋다.
설정 파일은 `tsc --int`만 실행하면 생성된다.

TS의 설정들은 어디서 소스 파일을 찾을지, 어떠한 종류의 출력을 생성할지 제어하는 내용이 대부분이다.
그런데 언어 자체의 핵심 요소들을 제어하는 설정도 있다.
대부분의 언어에서는 허용하지 않는 고수준 설계의 설정이다.

설정을 제대로 사용하려면, `noImplicitAny` 와 `strictNullChecks`를 이해해야 한다.

### noImplicitAny

`noImplicitAny`는 변수들이 미리 정의된 타입을 가져야 하는지를 제어한다.
다음 코드는 `noImplicitAny`가 해제되어 있을 때에는 유효하다.

```ts
function add(a, b) {
  return a + b;
}
```

편집기에서 add 부분에 커서를 올려보면 TS가 추론한 함수의 타입을 알 수 있다.

```ts
function add(a: any, b: any): any;
```

any를 코드에 넣지 않았지만, any 타입으로 간주하기 때문에 이를 `암시적 any`라고 부른다.

그런데 같은 코드임에도 `noImplicitAny`가 설정되었다면 오류를 띄운다.

```ts
function add(a, b) {
  // ~ 'a' 변수에는 암시적으로 'any' 형식이 포함됩니다.
  // ~ 'b' 변수에는 암시적으로 'any' 형식이 포함됩니다.
  return a + b;
}
```

이 오류들은 명시적으로 :any라고 선언해주거나 더 분명한 타입을 사용해서 해결할 수 있다.

```ts
function add(a: number, b: number): number {
  return a + b;
}
```

TS는 타입 정보를 가질 떄 가장 효과적이기 떄문에 가능한 경우라면 `noImplicitAny`를 설정해야 한다.

그렇다면 언제 `noImplicitAny`설정을 해제할까?
JS로 되어있는 기존 프로젝트를 TS로 전환하는 상황에서는 필요하다.
주의할 점은 이러한 설정이 임시라는 것이며 최대한 빨리 설정을 복원해야 한다.

**noImplicitAny** 설정이 없는 TS는 JS와 다를바가 없다.

### strictNullChecks

`strictNullChecks`는 null과 undefined가 모든 타입에서 허용되는지 확인하는 설정이다.

```ts
const x: number = null; //정상 null은 유효한 값이다.
```

그러나 strictNUllChecks를 설정하면 오류가 발생한다.

```ts
const x: number = null; // ~'null' 형식은 'number' 형식에 할당할 수 없습니다.
```

null 대신 undefined를 써도 같은 오류가 발생한다.
만약 null을 허용하려고 한다면, 의도를 명확하게 드러냄으로써 해결할 수 있다.

```ts
const x: number | null = null;
```

만약 null을 허용하지 않으려면 이 값이 어디서부터 왔는지 찾아야 하고, null을 체크하는 코드나 단언문을 추가해야한다.

```ts
const statusEl = document.getElementById("status");
statusEl.textContent = "Ready";
// ~~~ 'statusEl' 은 null일 수 있습니다.

if (statusEl) {
  statusEl.textContent = "Ready"; // 정상 null은 제외
}
statusEl!.textContent = "Ready"; // 정상, el 이 null이 아님을 단언
```

이러한 형태로 if 구문을 사용하는 것을 **타입 좁히기** 또는 **타입 정제** 라고 부른다.
타입 단언은 TS 역할이지만, 런타임에도 영향을 미칠 수 있다.

`strictNullChecks`는 null과 undefined 관련된 오류를 잡아내는 데 많은 도움이 되지만, 코드 작성을 어렵게 한다.
새 프로젝트를 시작한다면 가급적 `strictNullChecks`를 설정하는 것이 좋지만, TS가 처음이거나 JS코드를 마이그레이션 하는 중이라면 설정하지 않아도 좋다.

### 다른 설정들

언어에 의미상 영향을 미치는 설정들 중에 `noImplicitAny`와`strictNullChecks` 만큼 중요한 설정은 없다.
이 모든 체크를 설정하고 싶다면 strict 설정을 하면 된다.
TS에서 strict 설정을 하면 대부분의 오류를 잡아낸다.

`tsc --init` 으로 프로젝트를 생성한다면 기본적으로 strict 모드가 설정된다.
strict 모드보다 더 엄격한 설정도 있다.
코드에서 더 많은 오류를 찾아낼 수 있도록 설정을 추가할 수 있다.
예를들면 `nuUncheckedIndexedAccess` 옵션이 있다.
이 옵션은 객체와 배열 접근에 관련된 오류를 잡는 데 도움이 된다.
아래 예제는 strict 모드에서 오류가 없는 코드다.

```ts
const tenses = ["past", "present", "future"];
tenses[3].toUpperCase();
```

`nuUncheckedIndexedAccess` 옵션을 설정하면 오류가 발견된다.

```ts
const tenses = ["past", "present", "future"];
tenses[3].toUpperCase();
// ~~~개체가 'undefined'인 것 같습니다.
```

### 요약

- TS 컴파일러는 언어의 핵심 요소에 영향을 미치는 몇 가지 설정을 포함하고 있다.
- TS 설정은 커맨드 라인을 이용하기보다는 tsconfig.json을 사용하는 것이 좋다.
- JS 프로젝트를 TS로 전환하는 것이 아니라면 noImplicitAny 를 설정하는 것이 좋다.
- 'undefined는 객체가 아닙니다' 같은 런타임 오류를 방지하기 위해 strictNullChecks를 설정하는 것이 좋다.
- TS의 타입 체크를 충분히 활용하기 위해 strict 설정 사용을 권장한다.

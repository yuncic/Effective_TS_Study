# 아이템7 타입을 값의 집합이라고 생각하기

런타임에 모든 변수는 JS 세상의 값으로 부터 정해지는 각자의 고유한 값을 가진다.
그러나 코드가 실행되기 전, TS가 오류를 체크하는 순간에는 타입을 가지고 있다.
'할당 가능한 값의 집합'이 타입이라고 생각하면 된다.
이 집합을 타입의 '범위'라고 부르기도 한다.

가장 작은 집합은 아무 값도 포함하지 않는 공집합이며, TS에서는 never 타입이 이에 해당된다.
never 타입으로 선언된 변수의 범위는 공집합이기 때문에 아무런 값도 할당할 수 없다.

never는 타입 계층의 가장 아래에 위치하기 때문에 최하위 타입이라고 불리기도 한다.

그 다음으로 작은 집합은 한 가지 값만 포함하는 **리터럴 타입**이다.
_다른 프로그래밍 언어에서는 종종 유닛 타입으로 불린다._

```ts
type A = "A";
type B = "B";
type Twelve = 12;
```

두 개 혹은 세 개로 묶으려면 **유니온 타입**을 사용한다.

```ts
type AB = "A" | "B";
type AB12 = "A" | "B" | 12;
```

즉, 유니온 타입은 합집합을 의미한다.

다양한 TS오류에서 '할당할 수(assignable)'라는 문구를 볼 수 있다.
이 문구는 집합의 관점에서 '~의 원소(값과 타입의 관계)' 또는 '~의 부분 집합(두 타입의 관계)'을 의미한다.

```ts
const a: AB = "A"; // 정상, 'A'는 집합 {'A','B'}의 원소이다.
const c: AB = "C"; // 에러, 'C'형식은 'AB' 형식에 할당할 수 없다.
```

원소를 서술하는 방법도 있다.

```ts
interface Identified {
  id: string;
}
```

어떠한 객체가 string으로 할당 가능한 id 속성을 가지고 있다면 그 객체는 identified이다.
구조적 타이핑 규칙들은 어떠한 값이 다른 속성도 가질 수 있음을 의미한다.
함수 호출의 매개변수에서도 다른 속성을 가질 수 있다.

```ts
interface Person {
  name: string;
}

interface Lifespan {
  birth: Date;
  death?: Date;
}

type PersonSpan = Person & Lifespan;
```

& 연산자는 두 타입의 인터섹션(교집합)을 계산한다.
교집합이라면 Person타입과 Lifespan 타입의 공통 속성이 없기 때문에,PersonSpan 타입은 공집합(never)이지 않을까?
아니다.

타입 연산자는 인터페이스의 속성이 아닌, 값의 집합(타입의 범위)에 적용되기 때문이다.
그리고 추가적인 속성을 가지는 값도 여전히 그 타입에 속한다.
그래서 person과 Lifespan을 둘 다 가지는 값은 인터섹션 타입에 속하게 된다.

## 다시 짚고 가자! 속성의 집합과 값의 집합

TS에서 타입은 속성의 모음이 아니라, 그 타입을 만족하는 값(객체)들의 집합이다.

교집합(&)은 Person타입과 Lifespan타입에 모두 속해야한다.
name 속성도 가지고 있어야하고, birth와 death 속성도 가지고 있어야 한다.
그래서 오히려 값의 범위는 좁아지고, 필요한 속성은 늘어난다.

합집합(|)은 Person타입과 Lifespan타입 중 최소 하나만 만족해도 된다.
그래서 오히려 값의 범위는 넓어지고, 필요한 속성은 줄어든다.

```ts
// 정상
const ps: PersonSpan = {
  name: "jason",
  birth: new Date("1920/07/25"),
  death: new Date("1990/02/12"),
};
```

이 규칙이 속성에 대한 인터섹션에서는 맞지만, 두 인터페이스의 유니온에서는 그렇지 않다.

```ts
type K = keyof (Person | Lifespan);
// ^? type K = never
```

앞의 유니온 타입에 속하는 값은 어떠한 키도 없기 때문에 유니온에 대한 keyof는 공집합이어야만 한다.

keyof 연산자는 '이 타입에 속하는 어떤 값이든 안전하게 접근할 수 있는 키'를 찾는다.

- Person | Lifespan (합집합)에 속하는 값은 Person일 수도 있고, Lifespan 일 수도 있다.
- 어떤 객체가 들어올지 모르는데, name 키를 접근하면 그 객체가 Lifespan일 때 에러가 난다.
- 마찬가지로 birth 키를 접근해도 그 객체가 Person일 때 에러가 난다.
- 따라서 두 타입 중 어떤 값이 들어오든 보장되는 공통 키(Key의 교집합)를 찾아야 하는데, 두 타입은 공유하는 키가 없으므로 never(공집합)가 됩니다.

조금 더 일반적으로 PersonSpan 타입을 선언하는 방법은 extends 키워드를 쓰는 것이다.

```ts
interface Person {
  name: string;
}
interface PersonSpan extends Person {
  birth: Date;
  death?: Date;
}
```

타입이 집합이라는 관점에서 extends의 의미는 '~에 할당할 수 있는'과 비슷하게, '~의 부분집합' 이라는 의미로 받아들일 수 있다.
PersonSpan 타입의 모든 값은 문자열 name 속성을 가져야한다.

extends는 보통 인터페이스에 필드를 추가하는 데 사용되지만, 이미 존재하는 필드의 부분집합을 만들 때에도 사용된다.

```ts
interface NullyStudent {
  name: string;
  ageYears: number | null;
}

interface Student extends NullyStudent {
  ageYears: number;
}
```

이때 Studnet는 NullyStudent의 서브타입이며 NullyStudent는 Student의 슈퍼타입이다.
반대로 ageYears를 확장하려고 하면 오류가 발생한다.(부모 집합을 거스르는 행위이니까)

### 요약

- 타입을 값의 집합으로 생각하면 이해하기 편하다.(타입의 '범위').
  이 집합은 유한(boolean 또는 리터럴 타입)하거나 무한(number 또는 string)하다.
- 타입스크립트 타입은 엄격한 상속 관계가 아니라, 겹쳐지는 집합(벤 다이어그램)으로 표현된다.
  두 타입은 서로 서브 타입이 아니더라도 겹쳐질 수 있다.
- 타입 연산은 집합처럼 적용된다. A|B의 범위는 A와 B의 유니온(합집합)이다.
- 상속은 '할당 가능'으로, 서브타입은 '부분집합'으로 생각하자.

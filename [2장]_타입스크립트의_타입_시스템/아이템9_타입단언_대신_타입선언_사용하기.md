# 아이템 9 - 타입 단언 대신 타입 선언 사용하기

TS에서 변수에 값을 할당하고 타입을 부여하는 방법은 두 가지다.

```ts
interface Person {
  name: string;
}
// 1번 방법 - 타입 선언
const alice: Person = { name: alice };

// 2번 방법 - 타입 단언
const bob = { name: bob } as Person;
```

타입 선언을 하면 할당 되는 값이 해당 타입(인터페이스)를 만족하는지 검사한다.
타입 단언은 강제로 타입을 지정한다.

### ! 타입 단언

타입에 null이 포함되어 있지만, 문맥상 null이 될 가능성이 없다는 것을 알고 있다면 타입 단언으로 null을 제외할 수 있다.

```ts
// as 로 단언
const elNUll = document.getElementById("foo") as HTMLElement;

// !로 단언
const elNull = document.getElementById("foo")!;
```

접두사로 쓰인 `!`는 boolean의 부정문이지만, 접미사로 쓰인 `!`는 그 값이 null이 아니라는 단언문으로 해석된다.

### 옵셔널 체이닝

null일 가능성이 있는 객체의 속성이나 메서드를 사용할 떄는 **옵셔널 체이닝** 연산자 `?.` 를 사용하면 편하다.

```ts
document.getElementById("foo")?.addEventListener("click", () => {
  alert("Hello");
});
```

a?.b 는 JS구문으로서 런타임에 객체의 null 여부를 평가한다.
a!.b 는 TS 구문으로서 컴파일 후에 a.b로 바뀐다.
만약 런타임에 객체가 null이었다면 예외가 발생한다.

a?.b 가 a!.b 보다 안전하지만 항상 정답은 아니다.
만약 foo엘리먼트와 이벤트 리스너가 반드시 필요한 경우라면 차라리 오류를 발생시키고 수정하는 것이 나을 수 있다.

### 요약

- 타입 단언(as)보다 타입 선언(:Type)을 사용해야 한다.
- 화살표 함수의 반환 타입을 명시하는 방법을 터득해야 한다.
- TS보다 여러분이 타입 정보를 더 잘 알고 있는 상황에서는 타입 단언문과 null 아님 단언문(!,?.)을 사용하면 된다.
- 타입 단언을 사용할 때는 그 이유를 주석으로 다는 것이 좋다.
